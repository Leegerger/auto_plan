# Bonding 求解验证原型，第一阶段

后续证据见[第二阶段报告](phase-two.md)：全规模固定数量顺序实验、数量修复的失败与候选、边界核对，以及范围外切机演练。本文件保留第一阶段记录，其“尚未验证”描述以当时状态为准。

关联决策：[哪条求解路线能通过规则校验和 30 秒／2 分钟验证？](https://github.com/Leegerger/auto_plan/issues/16)。实验日期为北京时间 2026-10-13。本目录是可抛弃资产，不合入产品。已确认业务补充记在议题评论，本报告只记录实现范围、实验与下一批样本提案。

## 本阶段结果

完成日内顺序口径的六轮用户评议，并提供 [单文件演练](order-prototype.html)。浏览器直接打开即可，无服务、外部依赖或保存动作。支持六组引导案例及自由输入，展示每个机种对的原关系、候选关系及新增计数。已核对脚本语法与七个案例算术；没有声称完成浏览器交互验收。

求解实验覆盖一日、一条线、两个不同 Recipe 的机种，起始 Recipe 未知，CT 为零、双良率为一，同周需求，无锁定、执行事实或跨周确认。枚举活动机种集合和两种顺序，求解各自数量；在这个限定域中，重复回访只会增加切机且不增加可用容量，不会改善前置目标。该结论不外推到多日、多 Recipe 或重复基线。

每路线运行四个固定边界例和同一组 100 个随机小例，种子 160013，单线程，只跑一轮。单例时间包含本例建模、求解和精确校验；每路线首例另包含求解库的首次加载，后续例使用热进程。子进程时间还包含 Python 启动、枚举核对和报告写入。它们不是浏览器端到端时间，也不是同一实例五次冷／热重复，不据此给路线做性能排名。

## 精确边界与证明范围

固定活动集合与顺序后，连续工时的存在条件为 `sum(24*(q_i-1)/C_i) < T-S`。代码按本例的产能及剩余工时分母构造公分母，转为整数分子严格差至少为一，未规定任何工时网格。该转换仅针对本实验的单日子问题。

独立校验器不用求解矩阵的缩放系数，以 Python Fraction 直接计算各 Recipe 的严格下界，将正剩余工时均分，得到可核验的有理工时。枚举器遍历需求以内所有整数数量及顺序，独立比较 33 层向量。两种求解器一致不是通过标准，与枚举最优值一致且通过精确校验才计通过。

- 两 Recipe 的 C=1000、T=1、切机0.95、各需求2片，三个路线都得到各投入2片、工时各 `1/40`。
- 将 T 改为0.998，正好落在合计严格下界时，各2片不可行，最优合计降为3片。不能靠浮点容差接纳各2片。
- 零工时、零产能及非对称切机包含在样本中。
- 本域只有第一周有需求，最终缺口等于按时缺口。其余28个缺口坐标恒为零。覆盖层先最优并固定，再求数量变动；固定顺序分支的切机及顺序分数为常数，最后在全部分支之间比较完整向量。没有用加权和替代优先级。
- HiGHS 的浮点最优状态本身不是精确证明；这里的精确最优依据是限定域独立枚举。CP-SAT 的整数状态也仅针对已建的限定模型。
- 构造起点先每个活动机种投一片，再在容量允许时逐片增加，不用枚举最优答案作提示。它只是混合路线的起点实验，尚未实现局部邻域修复。

## 已保留的失败

第一次在同一进程依次加载 CP-SAT 和 HiGHS，HiGHS 抛出 `_ZN5Highs13releaseMemoryEv` 缺失符号，104次调用均未进入求解。CP-SAT两种方式仍得到208个一致结果。原始记录保留在 [首次失败](initial-import-failure.json.gz)，没有并入成功分母。

随后将每条路线放入独立子进程，HiGHS正常加载，三条路线各完成104例。现有证据支持该安装组合需要进程隔离的实验处理；未调查所有库版本组合，不将此失败解释成HiGHS不适合业务，也不据此决定生产架构。

## 重跑

实测解释器为 Python 3.14.2。主机会话默认的 Python 3.13.11 与实验虚拟环境不同，版本以 [环境记录](environment.json) 为准。使用当前环境可运行：

```sh
/tmp/bonding-solver-wayfinding/venv/bin/python docs/prototypes/solver-validation/small_experiment.py /tmp/bonding-small-results.json
```

重新安装时：

```sh
uv venv --python 3.14.2 /tmp/bonding-small-venv
uv pip install --python /tmp/bonding-small-venv/bin/python -r docs/prototypes/solver-validation/requirements.txt
/tmp/bonding-small-venv/bin/python docs/prototypes/solver-validation/small_experiment.py /tmp/bonding-small-results.json
```

所有 Python 包已固定版本，环境记录包含已安装包 RECORD 的摘要，该摘要不等于安装 wheel 的哈希。三个子进程顺序运行，各用一个线程。未配置实验容器限额，未测其他服务器进程负载。运行时失败会保留在结果中，程序以非零码退出。

API依据：[OR-Tools CP-SAT 官方说明](https://developers.google.com/optimization/cp/cp_solver)、[HiGHS Python 官方示例](https://ergo-code.github.io/HiGHS/stable/interfaces/python/example-py/)。安装版本及实际运行结果是本次能力证据，文档不作为性能证据。

## 全规模样本分布

共同规模为18条线、40个机种、105个生产日，从2026-10-12至2027-01-24，覆盖四个月份。用户在Q7接受常态Recipe数量、可替代线体及日内段数分布。先固定快照、预期和参考方案再调参。

| 组别 | 提议配置 | 要回答的问题 |
| --- | --- | --- |
| 常态 | 20个Recipe，每Recipe两个机种，每Recipe可上3至6条线；每个开工日每线1至3段 | 多机种共享Recipe、可替代线体与日内顺序能否正确求解 |
| 组合差异 | 10个Recipe且每个有较多机种；40个Recipe且每机种独有Recipe | 同Recipe汇总与不同切机密度对路线的影响 |
| 线体稀缺 | 关键Recipe只能上1至2条线 | 局部调整范围不足、瓶颈和前后固定安排 |
| 容量负载 | 由已校验参考方案生成宽松与紧张需求，再增加需求制造可执行但有缺口的案例 | 返回质量不得劣于用户确认的参考方案，不能把需求不足报成硬无解 |
| 跨月／日历 | 月度产能与良率变化、CT含小数、Holiday与线体开工例外、跨日切机 | 同输入来源的精确取整、日历与工时归属 |
| 确认／保护 | 物料及出货多批额度不足、整周禁令、锁定与范围外边界 | 有效覆盖与待确认分开，拒绝未经授权的改变 |
| 硬冲突 | 锁定数量超过当日合法容量等可明确证明的矛盾 | 与未全满足需求、超时未找到和邻域无解分别报告 |

1至3段是样本分布，不是求解模型的段数上限。其他变体尚未生成，参考方案的质量门槛仍需用户评议。
