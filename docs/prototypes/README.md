# 手动排程交互原型（可抛弃）

对应议题：[批量填量、交换机种与改量顺延应怎样操作？](https://github.com/Leegerger/auto_plan/issues/9)。

## 第三轮：手动编辑流程

用户已确认 Q1–Q17 的业务选择。页首提供追加填量、交换生产段、改量顺延、比较与恢复、其他手动操作五个入口。除追加填量外，各入口为独立固定场景，用于验证交互；数据不互相影响。

- 追加填量：可插到相同 Recipe 附近，保持原有段相对顺序；示例只按日内切换次数选择插入点，完整前后 Recipe 衔接未实现。草稿写入和撤销同时保存数量及段顺序。
- 交换：依次选两段、预览、检查，机种与数量整体换位；数量差、顺序差、切机次数和时长分别显示。支持同日、跨日、跨线场景；数量锁定和不可生产关系会阻止示例应用。
- 顺延：优先满足当前段目标量，溢出段在授权线体和截止日内连锁挤动未锁定后续段。保护锁定数量、跳过 Holiday，截止日未排量与待确认预排量分开显示。减量不前移后续计划。
- 恢复：选择历史范围，显示采用版、当前草稿、历史量和当前保护状态；处理锁定、锁零及已执行冲突。范围或锁定变化使旧检查失效；恢复草稿与明确采用是两个动作。
- 其他操作：单段复制默认新增，覆盖另设入口；移动守恒、拆分不增加合计、清空不等于锁零、日内排序单列顺序差。批量复制保留日期间隔及日内顺序，默认保留源线体，支持逐条指定目标线。

## 已确认的追加填量流程

根据用户 Q1–Q9 的反馈，采用周表格为主、点击显示日内顺序详情的结构。数量输入表示指定机种的新增投入总量。

1. 选择机种，只显示可生产的线体。
2. 输入追加量及开始、截止生产日。
3. 开始后，高亮范围内有剩余能力的日期与线体，并显示可追加数量。
4. 点击某条线的“按日期填量”，按日期先后逐日尽量填满，直到总量分完或达到截止日期。
5. 未分配量保留，由用户继续选择下一条线；不自动换线或延长范围。
6. 核对逐日明细，可以取消部分改动；选取变化使旧校验失效，须重新检查后才能写入临时草稿。
7. 写入后可撤销；刷新清除全部示例修改。

已确认交换将机种及数量作为整体移动，支持同日、跨日、跨线，预览后校验。改量顺延仅移动放不下的部分，限定同线与截止日。复制粘贴、清空、移动、拆分和日内排序纳入后续原型。

## 打开

直接用浏览器打开 `scheduling-interaction-prototype.html`，或在仓库根目录运行：

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory docs/prototypes
```

访问 `http://127.0.0.1:8765/scheduling-interaction-prototype.html`，用页首按钮切换流程。也可用 `?flow=swap`、`?flow=ripple`、`?flow=version`、`?flow=edit` 直接进入演练。第一轮三种布局保留在提交 `bfd0d8e`，第二轮在 `1dc22c2`。

## 示例路径

- 默认 A、追加 10,000 片、10/8 至 10/16：选 L01，分配 9,200、剩余 800；再选 L03，追加剩余 800。
- 预览中取消 L01 10/8 的 1,200 片，未分配量变为 1,200，写入按钮禁用，必须重新检查。
- L01 10/9 的 A 数量锁定；L03 10/8 的 B 锁零；周末 Holiday；L03 10/9 无剩余容量。
- 手工核对了日期顺序、总量尾数、逐线继续、未分配余额、部分选取失效、草稿写入、撤销和机种筛选。
- 第三轮核对了追加段插入及顺序撤销、同日交换数量差为零、跨线数量锁定阻止交换、连锁顺延、减量不前移、恢复保护冲突、部分恢复重检和批量日期/线体映射。
- 顺延默认例：10/12 A 从 600 改到 1,000，使 C 400 溢出；越过 10/13 的 C 数量锁定与 10/14 的 Holiday，在 10/15 挤出 A 200、C 200 到 10/16。固定情景将周五这 400 标为待出货确认。

## 明确限制与待定项

- 这是交互草图。剩余工时和可追加量是固定情景值，不是完整业务计算；示例假定已经预留切机工时，不能用于验证正式产能取整或前后 Recipe 衔接。正式版本必须沿用前置决议计算真实能力。
- 未实现双良率、CT、真实确认额度、执行事实录入或正式版本存储。恢复、确认与采用只在明确标注的独立情景中演练。
- 顺延场景仅使用同 Recipe、同速的 A/C 演示队列与保护边界，不据此验证完整多 Recipe 容量与切机规则。
- 交换次数和时长采用明确标注的日初状态及有向耗时示例；真实跨日、前后边界及普通空闲抵扣仍由完整规格约束。
- 原型里的暂定界面细节仍需用户试用反馈，不能把演练检查通过当成生产可执行性证明。
- 示例仅 A/B/C 三个机种；尚未验证约 40 个机种下的完整密度。
- 本议题保持打开，等待用户继续反馈；不会把粗原型直接变成生产实现。
