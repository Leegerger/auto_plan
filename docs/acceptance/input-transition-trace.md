# Passive input transition diagnosis

The disposable adapter supports `--input-transitions /owned/path/trace.ndjson`. It is disabled by default and accepts only MemoryInputStore. Product entrypoints and Oracle stores do not use it. The trace supports protocol diagnosis, not a timing or load acceptance claim.

Each actual input GET/preview/apply response carries an opaque `X-Auto-Plan-Test-Input` identifier. Its newline-terminated record binds the method/path, optional version query, original consumed request length/hash, actual response status/completion and events in one process's monotonic clock domain. Headers, cookies, credentials and exception inputs are not recorded. Unread request tails stay unread and incomplete. A disconnect or handler failure without a response keeps the status and completion unknown.

The observer forwards each original receive/send message once. It wraps the memory adapter's original read/update and lock calls, records the version actually passed into the original transform, and invokes that transform once. The version at lock release is observed by attribute access under the already-held original lock. A candidate advance is distinct from a returned stored result: activity credit appears only after the original update returns. An unchanged acknowledgment has zero credit. Failed transforms have zero credit and preserve their actual error type without logging input values. These events do not establish an Oracle commit timestamp.

The public two-actor regression deliberately coordinates an accepted V1 preview, another actor's genuine V1→V2 commit and the unchanged normalized first command's apply409. It verifies V1/V2 history, a no-op200 at V2, a real V2→V3 advance, exact complete input contents, unchanged Plan and demand history and R/A0. This is a small protocol control, not naturally occurring starvation. Separate controls verify unchanged receive messages, an unconsumed tail, disconnects, no extra store/transform/lock calls and context cleanup.

The original100 full first-import failure remains unchanged: 47 known genuine acknowledgments, actor2's33 successful previews followed by33 actual apply409 replies, no readiness/native upload, and unconfirmed final source/acknowledgments/restoration. Its HTTP-only records cannot identify the actual atomic checked version or split browser/controller/server delay. This new observer has not run that workload. A later browser trace must correlate the same normalized command and passive JSON/DOM/native-event phases, retain separate clock domains and preserve all existing writers, cadence, source guards, setup limits and action clocks. No full retry or product admission change follows from this functional helper.

## Browser consumption correlation

The separate opt-in `input-trace.browser.mjs` runs only the declared small two-actor Inputs.vue protocol. Its hook records primitive native click, fetch/JSON-consumption, current-preview DOM readiness and resource timing metadata. Original fetch/JSON calls run once and preserve returned values and errors. Parsed response objects are never exported as immutable proof; the unchanged network request/response files and their hashes provide that proof. Existing source/body/capture checks remain before native apply. No product code, source admission, cadence, deadline or acceptance gate changes.

`input-trace-join.mjs` binds each actual response ID to one complete server record, original consumed request bytes, the accepted normalized preview command, enabled native action, JSON pin and current DOM-ready marker. Missing/duplicate IDs, partial receipt, changed bodies/pins and stale markers fail. Browser, Node and server timestamps retain separate clock domains; JSON consumption includes transfer/scheduling and is not pure parser CPU time.

The first small control starts with two literal lines/models and an empty Plan. A previews V1, B genuinely commits V2, A's unchanged native apply receives409, and A uses the real reload/preview/apply controls to commit V3. V1/V2 and Plan/demand history remain unchanged. The declared disposable protocol ends with both names changed at V3; closing its processes does not claim original-name restoration. Its successful correlation does not reproduce100's natural readiness starvation, establish a full-size result or authorize another full first-import attempt. The original116 server-only evidence remains insufficient for browser attribution.

The final join validator requires unique finite native/fetch/header/JSON markers, matching method/path/client/native identities and nondecreasing order. Preview JSON must precede its current DOM-ready marker and native apply. Equal timestamps are valid. Resource callback delivery may occur later than every request phase.

The producer's clock_domain contains a page label, not a document timeOrigin/token. That label alone cannot prove a same-document claim. A stronger claim must bind the exact independently retained browser export bytes/hash and page index; resource attribution also needs the trusted page origin. The validator reports these attributions as unknown when those bindings are absent and rejects an explicitly requested claim. It never invents a document identity from timestamps.

For a resource claim, exactly one same-page URL must start within the actual fetch-start/header window, finish no later than JSON completion and have a finite callback timestamp at or after responseEnd. Missing, contradictory, duplicate or mixed-clock evidence stays unknown. The original three small joins can be replayed with their unchanged export/config/body hashes and those explicit bindings. No new browser run or raw final-GET body proof follows from that replay; the122 final-GET persistence limitation remains.

A retained response-body claim separately requires the original raw response bytes, the producer's existing response_sha256 and exact parsed-content equality. The original116 server trace did not capture a response digest/length, so server response-byte attestation remains unknown even when retained-body attribution is confirmed. The status-bearing fetch_received marker must match the actual HTTP status; JSON markers bind through its unique request/sequence. The producer did not separately record JSON statuses; none are invented, and any supplied contradictory status fails.

## Original first-import wiring

`AUTO_PLAN_INITIAL_IMPORT_INPUT_TRACE=1` enables the same observer and primitive browser hook in the original first-import worker. The flag is off by default. It adds no business source, gesture, editor hold, retry or readiness rule. The original180s setup,150s action,15s cleanup,345s absolute and365s Node limits remain unchanged. The original native File change owns the upload clock. Public full-snapshot evaluation still uses APIRequestContext and has no browser fetch/JSON claim.

Enabled input editor replies retain their actual opaque server ID and Node-local body-await, capture/hash/write and JSON-parse intervals. The original request/body/source checks stay before apply. The disabled editor path retains its original statements. Parsed Vue objects never become immutable proof. Native fetch/JSON behavior is the already qualified hook, called once.

The worker binds actual product/helper/dist bytes, the fixture manifest, declaration, source/reference/action/import/workbook pointers and page origin in a separate `input-trace-config.json`. It retains primitive browser and Node buffers plus a small attempt index. Browser export uses at most500ms of the remaining published cooperative cleanup window and starts no work after its cutoff. Its timer is unref'ed. Missing or closed pages and interrupted exports remain unknown; the independent guardian and its resource deadlines remain authoritative. Instrumentation export failure cannot skip owned resource cleanup.

Full body verification runs after worker exit, outside teardown:

    node frontend/tests/acceptance/input-trace-replay.mjs /absolute/owned/output

The read-only replay verifies the separately retained config, browser batch, index, ledger and existing body hashes before joining actual preview/apply IDs. It requires complete newline-terminated server records and exact normalized commands, statuses, consumed pins and browser chronology. Missing, partial, duplicate or mismatched evidence earns no claim. It preserves each resource claim as confirmed or unknown rather than requiring an unavailable resource event. Server response-byte attestation and complete raw reload-GET bodies remain unknown. Replay cannot establish new acknowledgments, final source closure or restoration after an interruption.

The132 implementation retained an actual122 accepted-response RED after extracting the original body/capture/parse statements into a callable. Its immutable body and original calls were intact, while the server ID and phase attribution were absent. The corrected callable and all three original immutable joins pass without a new browser. This does not rerun or resolve original100's readiness failure, its47 known acknowledgments or its unknown final source/acknowledgments/restoration. No full workload, natural-starvation or SLA result follows from the wiring.

## Durable Node reply diagnostics

Under the same opt-in, each existing input-attempt journal write now includes the actual response ID and the same bounded six Node phase primitives already recorded in memory. No extra per-phase IO, body read, parse or capture is added. The disabled inline editor path and original callback fields remain unchanged. A completed callback's serialized primitives survive loss of the final export; an in-flight callback or partial prefix can still remain unknown. This small metadata payload adds work to the existing write and establishes no performance improvement.

The separate `input-driver-replay.mjs` reads hash-bound journal/server/owner artifacts and retained raw request/reply files. Its bindings JSON has `journal`, `server` and `owner` objects containing absolute `path` and SHA256 `sha256`, plus `artifacts_root` for the captured `bodies/` directory's parent. The owner is the retained functional-phase artifact with the actual worker PID/start/attempt. After all resources close, use a new result path:

    node frontend/tests/acceptance/input-driver-replay.mjs /absolute/new/bindings.json /absolute/new/driver-result.json

The result is explicitly server/driver diagnostics. It rejects duplicate or mismatched IDs, methods, paths, statuses, request hashes/lengths, retained body hashes, incomplete records and contradictory Node phase order/domain. It binds the Node domain to the separately retained worker PID. Only complete retained callbacks can be correlated; missing or unjournaled attempts are not inferred. The CLI refuses an existing output file.

Node body-await/capture/JSON intervals stay in their own clock domain. They include scheduling and the original capture work and are not pure parser CPU. Browser consumption, native clicks, consumed pins and server response-byte attestation remain unknown. Source/acknowledgment/restoration remain unconfirmed by this diagnostic. The strict browser/document replay and its missing-binding failure are unchanged; no fallback converts driver correlation into a protocol pass.

The145 regression uses an immutable143 request/reply and uniquely matching server record in a new callable observation. Its journal originally dropped an ID already present in memory. That RED and its correction establish the durability seam, without creating old143 client phase timestamps. Original143's interrupted setup, absent final buffers and unknown final source/acknowledgments/restoration remain unchanged. No browser or full-workload retry follows from this change.
