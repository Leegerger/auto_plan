# Passive input transition diagnosis

The disposable adapter supports `--input-transitions /owned/path/trace.ndjson`. It is disabled by default and accepts only MemoryInputStore. Product entrypoints and Oracle stores do not use it. The trace supports protocol diagnosis, not a timing or load acceptance claim.

Each actual input GET/preview/apply response carries an opaque `X-Auto-Plan-Test-Input` identifier. Its newline-terminated record binds the method/path, optional version query, original consumed request length/hash, actual response status/completion and events in one process's monotonic clock domain. Headers, cookies, credentials and exception inputs are not recorded. Unread request tails stay unread and incomplete. A disconnect or handler failure without a response keeps the status and completion unknown.

The observer forwards each original receive/send message once. It wraps the memory adapter's original read/update and lock calls, records the version actually passed into the original transform, and invokes that transform once. The version at lock release is observed by attribute access under the already-held original lock. A candidate advance is distinct from a returned stored result: activity credit appears only after the original update returns. An unchanged acknowledgment has zero credit. Failed transforms have zero credit and preserve their actual error type without logging input values. These events do not establish an Oracle commit timestamp.

The public two-actor regression deliberately coordinates an accepted V1 preview, another actor's genuine V1→V2 commit and the unchanged normalized first command's apply409. It verifies V1/V2 history, a no-op200 at V2, a real V2→V3 advance, exact complete input contents, unchanged Plan and demand history and R/A0. This is a small protocol control, not naturally occurring starvation. Separate controls verify unchanged receive messages, an unconsumed tail, disconnects, no extra store/transform/lock calls and context cleanup.

The original100 full first-import failure remains unchanged: 47 known genuine acknowledgments, actor2's33 successful previews followed by33 actual apply409 replies, no readiness/native upload, and unconfirmed final source/acknowledgments/restoration. Its HTTP-only records cannot identify the actual atomic checked version or split browser/controller/server delay. This new observer has not run that workload. A later browser trace must correlate the same normalized command and passive JSON/DOM/native-event phases, retain separate clock domains and preserve all existing writers, cadence, source guards, setup limits and action clocks. No full retry or product admission change follows from this functional helper.
