# 精确容量与切机预览

业务编辑者打开「日内详情」，录入生产日期、线体、生产段顺序、机种、投入数量与精确工时。工时可填写任意精度的十进制文本或分数，例如 `0.024001`、`1/3`。默认展示四位小数，严格为正且小于 `0.0001` 的工时显示为 `<0.0001`。展开「查看精确值」可以复核计算使用的分数；展示值不参与容量计算。

每个生产日、线体、Recipe 的所有机种和拆分生产段共同分享一次向上取整的投入上限 `ceil(C × H / 24)`。同日各 Recipe 的生产工时与全部切机分配共用日可用工时。日可用工时来自工厂 Holiday、线体开工例外，以及分别维护的保养、实验占用。保养20小时加实验10小时可以维护，但该日不能安排正生产工时或正切机工时。

每次有向切机填写原 Recipe、目标 Recipe 和每日分配。每日分配总和必须精确等于维护的总时长；缺少已知不同 Recipe 的参数时按12小时计算并标记。切机分配事件与生产段使用同一个日内顺序编号，不能重复，也不能在未完成的跨日切机中穿插生产或另一切机。不同 Recipe 的零耗时切机也需保留一个零工时事件。相同 Recipe 无需切机。

起始 Recipe 可以保持未知，首次生产不扣切机。已知状态会跨空闲、Holiday 和保养保留。切机已使用的全部工时只计入对应日一次。普通空闲预算按日期和线体唯一维护，使用的空闲不能重复供给生产或另一切机；额外扣减时间等于总时长减去实际使用的空闲，最低为零。

标准导入资料只需提供投入数量和日内顺序。点击「按数量生成工时依据」可构造精确的生产、切机工时，并重新核验。构造器使用每个 Recipe 正投入所需的严格时间下界，检查所有日期区间的可用容量，依据实际剩余容量选择一个正有理数余量。没有固定最小工时或固定 epsilon。无法构造时返回日期、线体与原因；生成的依据仍需完整计划规则核验。

公开 API 均位于配置的 API 前缀下，只有编辑者可用，均不写入资料或计划：

- `POST /plans/evaluate` 接收 `{snapshot: EvaluationSnapshot}`，返回日容量、Recipe 汇总上限、切机次数及总时长／空闲／额外扣减、问题和冻结计算时间。
- `POST /plans/certificate/preview` 接收同样上下文，计划使用 `SourcePlan`，生产段不提供工时。返回 `{plan,evaluation,issues}`。容量依据无法构造时 `plan`、`evaluation` 为 `null`。

`auto_plan.plan_models` 定义计划、精确工时、执行事实及覆盖、周一快照、锁定、采用基线与计算时间的类型。维护资料继续使用原有 `InputSnapshot`。纯函数 `auto_plan.rules.evaluate` 接收完整上下文和精确计划，不读取时钟、数据库或求解器。`auto_plan.certificate.construct_hour_certificate` 是导入与页面共用的工时构造入口。`InputIndex` 由资料诊断和规则校验共用，统一解释产能、日历与有向切机缺失值。

纯规则快照必须冻结 `{as_of,window_start,weeks:15}`。`as_of` 包含时区，`window_start` 为生产周周一；投入、空闲与切机分配不得超出该十五周窗口。页面预览请求可省略此时间，由服务端时钟填写一次。历史与候选核验保留原计算时点。生产日期以北京时间08:00分界，时间转换使用 `production_time` 中的公共函数。

容量通过与完整需求核算分开报告。缺少关键良率或 Cycle Time 时，`computation_complete` 为 `false`，不能声称相关产出已经计算完成。产出、确认、事实与稳定性规则由同一快照和规则入口继续扩展；容量预览不证明现场连续切机条件。
