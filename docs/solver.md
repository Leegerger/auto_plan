# Scheduling candidates

`auto_plan.solver.solve(FrozenSolveInput, progress=None, should_stop=None)` computes candidates from one frozen shared draft. It does not write plans, create jobs, open Oracle connections, or update the adopted baseline. Editors submit durable calculations through `POST /jobs`, supplying a submission UUID, current shared revision, complete input version and latest adoption. They poll `GET /jobs/{job_id}` and retrieve candidate content through `GET /jobs/{job_id}/candidates/{candidate_id}`. These routes are relative to the configured API prefix. Unsaved browser operations are absent from the frozen shared source. The former `POST /plans/candidates/preview` endpoint returns HTTP 410 and directs clients to `/jobs`. See [calculation jobs](calculation-jobs.md) for persistence, UUID verification and application by server candidate reference.

A request explicitly selects `local`, `new_week` or `all_replan`, its date/line/model scope, and `hybrid`, `cp_sat` or `highs`. The default compute budget is 20 seconds for local work and 90 seconds for either explicit wider mode. A request can select at most three distinct candidates; the default is one. These compute budgets do not replace the accepted browser-to-result gates of 60 seconds for typical local work and 180 seconds for new-week/all-replan work. The [runtime acceptance record](validation/acceptance/runtime.md) identifies the measured scenarios and the deferred local/new-week end-to-end matrix.

A candidate contains its complete frozen source snapshot and tokens, request, exact resulting plan, replayable patch, complete CAP/CELL/REQ effects, evaluation, 33-layer objective, stage bounds and adoption eligibility. Its content hash binds the entire frozen provenance and candidate body. Applying a patch still requires the current PlanService input/revision checks and full replay/evaluation. Browser recovery must store a server candidate reference and selected change IDs, rather than copying a candidate plan into local intent storage.

The minimized vector contains all fifteen on-time gaps, all fifteen final gaps, Recipe-switch count, adopted-baseline weighted input change and daily order reversals. Fractions remain exact strings. A late improvement cannot offset an on-time loss. Preparing a starting plan never changes the adopted comparison baseline. Free input that does not cover demand is removed or rejected, while necessary rounded tails remain. Protected surplus is retained and reported.

The hybrid path prepares eligible input, constructs by cumulative demand and actual dated capacity, optimizes daily order before and after quantity repair, and repairs Recipe quantities with all other Recipe quantities and the global switching certificate fixed. Large construction batches receive incremental exact certificates and independent whole-plan checks before publication. A separate structural proposal may move between authorized dates/lines and create/delete segments while preserving facts, locks and outside work. New-week mode preserves existing rows and switching. It can use authorized idle capacity for new work. All-replan is an explicit mode and still protects facts and locks.

The retained CP-SAT and HiGHS local models jointly repair all authorized future Recipe quantities with fixed positions and switching. Current-day rows and their joint execution proof remain exact during these fixed-switch stages. Separate Recipe models fix the other quantities. Integer constraints encode aggregated per-Recipe capacity and strict rational time bounds, source output ceilings across lines, deterministic FIFO allocation, dated confirmation batch matching, whole-week bans, largest-remainder input shares, adopted-baseline weights and fixed-order reversal activation. Binary integer products represent the input-share numerator/division/remainder calculations. They do not impose a production-hour grid. Exact oracle cuts reject invalid Recipe/event or surplus arrangements without assuming monotonicity of apportioned shares. Every proposal then passes the complete independent evaluator and a strict full-vector comparison.

Tiny-domain enumeration is an additional check and neighborhood. Its bounded quantity/order table is explicitly named in its proof scope. Its search caps are not restrictions on the business API; larger inputs continue through construction and substantive native models. A finite table optimum, a fixed-switch optimum, and numerical HiGHS optimality never become a global scheduling proof. Native stage values omit fixed contributions; the candidate vector always contains the complete independently calculated values. CP-SAT optimal integer stage values have scoped exact lower bounds. HiGHS reports its numerical status without an exact lower-bound claim.

Production and switching hours use the shared exact certificate constructor. Outside rows, positions, switching and idle certificates remain fixed. Compatible unknown entering Recipe states may converge at the next preserved production event without rewriting outside work. An actual new or changed outside switch requires expanded scope. Current-day additions use `execution_rules.execution_certificate` and its explicit `current_day_witnesses`; no evaluator repairs missing proof. Executed associations come only from the common execution rule.

Each native solve starts a fresh exec process that loads exactly one library. Neither native library loads in the application/controller. `compute_environment` constructs the child environment from a small fixed allowlist and never copies Oracle, company-auth or other app/test secrets. No pool, connection or inherited descriptor enters the child. Solver threads obey the requested and detected CPU budget. Input size, variable count, output size and run time are bounded. A separate stop-file watcher calls each solver's interruption API independently of new incumbents. Ten seconds without cooperation causes forced termination. Only complete independently checked candidates reach the progress callback; durable commit remains the caller's responsibility.

`feasible`, `time_limit`, `stopped`, `incomplete`, `no_candidate` and `scope_conflict` describe different outcomes. A demand gap is allowed in an executable candidate. Pending confirmation is a separately marked preplan. Missing critical yield/CT does not become a complete zero-output recommendation. A constructor or neighborhood failure does not prove business infeasibility. A protected quantity above the exact whole-day upper bound carries a localized protected-capacity proof.

## Verification

`tests/test_solver.py` uses the public durable job, candidate, evaluation and replay APIs and the public compute stop callback. Expected values include independent small enumeration, fractional CT/yield arithmetic, quota ownership, zero-share bans, scope protection, locks, new-week preservation and actual current-day association/proof replay. Both native libraries run in fresh processes. `tests/test_oracle_solver.py` uses a disposable PLAN_TEST AP_TEST namespace for frozen shared reads, durable candidate calculation without changing the shared plan, candidate patch persistence and changed-input rejection.

`scripts/solver_small_oracle.py` imports no application code. Its five finite cases and its separately enumerated 0..2000-input quota case are recorded in `docs/validation/solver-small-oracle.json` and `solver-quota-oracle.json`. The latter obtains vector coordinates `(101,2,0,2)` at inputs 1070/1071; eligibility removes the extra piece at 1071. These are independent fixture oracles, not user-confirmed production reference plans.

`scripts/measure_solver.py` records the 18-line, 40-model, 20-Recipe, 105-day CPU diagnostics. The synthetic frozen future start avoids pretending that current-day capacity is confirmed. The empty, local and new-week artifacts live in `docs/validation/solver-scale-*.json`. The early diagnostic exceeded its nominal compute budget because of quadratic Pydantic switch comparisons; canonical document membership and incremental certificates removed that measured cost. These runs do not establish constrained-container, browser, network, Oracle-load, five-human or final deployed SLA acceptance. The complete application image and user-confirmed production references remain separate acceptance work.

The final solver branch regression after merging completed execution/reset helpers passed 199 tests with 25 opt-in skips in 95.99 seconds. Both native routes exercised the today/future scope case and preserved the confirmed current-day proof. The separate final PLAN_TEST solver persistence check passed in 12.06 seconds and cleaned its disposable namespace. These checks validate implementation behavior and persistence; they do not establish the final deployed performance gates.
