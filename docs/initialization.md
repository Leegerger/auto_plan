# 首次接入和需求变更

在「首次接入与需求」下载标准 Excel 模板。人工整理旧 Excel 后再填写模板；工具不会识别旧文件的颜色、合并单元格或公式。实际旧文件映射仍由议题22单独确认。

初始化工作簿保留「输入资料」模板的全部主资料、参数、日历和确认工作表，并增加以下工作表。可以把已维护的输入留空，仅提交需要更新的识别组合。

| 工作表 | 内容 |
| --- | --- |
| segments | 段编号、生产日期、线体、人工提供的日内顺序、机种、投入数量。服务器生成精确工时证书，不要求旧表提供工时。 |
| demands | 机种、需求周周一、WYYYYWW周别、完整整周需求。每个参与机种的十五周均须填写，零也要显式填写；包含已满足部分。 |
| coverage | 旧计划覆盖起止日期、线体列表、机种列表、覆盖内空白是否为零。已导入生产段须位于声明的覆盖内。未覆盖范围不成为旧零基线。 |
| reset | 外部快照批号、生产周周一、周一08:00截止时点、机种、在制品、带符号净余额。同一快照每个参与机种两项都必填。 |
| execution_facts | 按生产日、线体、机种的实际累计投入。相同组合不能重复；未知不能填写为零。 |
| execution_coverage | 已确认事实的起止日期、线体、机种与覆盖内空白是否为零。 |
| initial_states | 可选的线体起始Recipe；未知可留空，预览保留未知标记。 |
| settings | 仅一行：完整整周需求确认、已确认事实截止时点。 |

日期填写YYYY-MM-DD，月份YYYY-MM，截止时点填写包含时区的ISO时间，例如2026-10-12T08:00:00+08:00。列表以 `|` 分隔；编码本身含此字符时，可填写JSON字符串数组。布尔值填写true/false。标准列名及顺序以模板为准。也可在网页逐行编辑或粘贴带标准列名的制表符表格。

生产日以北京时间08:00分界。需求周从周一08:00到下周一08:00，当前窗口共十五周。周一日期与WYYYYWW必须一致；2025-12-29是W202601，2026-12-28是W202653。

预览不写入资料。发现任何错误，整批拒绝，返回工作表、行、字段和原因。确认首次导入后，输入、事实范围、外部重置标记、初始需求文件和待处理共享草稿在一次事务内生效；此时尚未采用。到「共享计划」核对并明确采用，才会建立稳定性比较基线。

初始现行计划已经完成外部本周重置。来源2000、净余额600、导入1400，导入后仍为1400，不再扣成800。本周不能再次系统重置或更正本周重置；外部重置有误时，核对后手工修改并重检。下周从工具采用版正常重置。

需求文件归属日期以北京时间自然日00:00分界，默认北京今天；可以修订启用日之后的历史日期。启用日的初始文件从零增加至完整周需求。同一天的新文件完整替换旧文件贡献，省略行表示撤回。不同日期按日期和原行序累计，每一步不得负数。相同内容的独立行都会计入；同日重复上传不会累加上一份文件。

「需求文件版本和独立行」保留旧版本、当前有效标记及各行身份。需求变更推进完整输入版本，保留计划位置和数量，不生成虚假的计划修订。历史计划快照继续显示当时的需求。

提交结果未知时页面保持只读，核实后才继续。浏览器只保存操作编号和导入类型，不保存完整初始化计划；服务器是资料真源。如果浏览器禁止本地存储，仍可明确提交，但需要保留页面完成核实。

部署时显式执行 `migrations/004_demands.sql`，不得通过页面或启动自动修改数据库结构。需求文件带压缩快照、SHA256及不可变触发器；需求操作编号与计划编号分开持久化。数据库仍复用应用原有连接池。
