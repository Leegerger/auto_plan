# 前端以排程工作流组织，并保留单一计划修改入口

## Status

Accepted

## Context

现有前端把输入资料、首次接入、共享保存、日间工时、计算任务、历史、稳定性与每周重置放在少数平级入口中。业务编辑者需要在同一页面穿过任务和历史才能调整计划，同一份计划也存在多个修改入口。主要使用者是每天处理排程的桌面端业务编辑者；手机与其他设备不在本次支持范围。

## Decision

前端采用工作流优先的信息架构：工作台、排程、需求与资料、版本与采用、系统管理。排程使用单周“线体 x 日期”矩阵、十五周导航和右侧检查面板。所有计划修改都进入同一个本机临时稿队列，并在计划工作区完成“预览 -> 共享保存 -> 正式采用”；计算、历史恢复与每周重置只产生本机操作，不直接改写共享草稿。首次接入只在尚无共享计划时提供入口。

视觉层以仓库根目录 `DESIGN.md` 的色板、字级、间距和组件状态为基础，但采用工作型密度与左侧导航，不照搬消费市场的照片、搜索栏、商品卡片和大留白布局。

## Considered Options

- 继续按数据对象和现有页面平级组织：迁移成本较低，但高频工作仍需跨页面拼装步骤。
- 按角色建立不同导航：短期可减少可见入口，但会让同一功能出现多套名称和位置。
- 将保存与采用强制移到独立版本页：审计边界清楚，但会增加每次排程操作的跳转和上下文丢失。

## Consequences

- 业务编辑者、查看者共用一套导航；权限只控制动作，不改变信息位置。
- 共享草稿、采用版计划与本机临时稿必须由全局计划状态统一呈现。
- 旧路由保留为重新导向入口，避免既有书签和测试突然失效。
- 完整编辑只承诺桌面浏览器；移动端适配不属于本次验收。
- `DESIGN.md` 作为视觉参考，项目实际 token 与组件规则记录在 `docs/frontend-design.md`。
