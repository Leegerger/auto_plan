# Oracle 作为唯一真源，使用服务端会话，不引入 Redis 和 JWT

多人内网排程工具需要即时撤销授权、可核实的保存结果和重启后可判定的任务状态。参考实现用无状态 JWT 登录，并用 Redis 保存后台任务进度；议题 17 只确认了 Oracle 19c 与 Docker 部署，没有确认 Redis 可用。因此新工具把会话、授权、草稿、采用版、幂等键和任务状态全部存入 Oracle，会话为服务端会话，浏览器只持有不透明会话号。

## Considered Options

- 沿用 JWT：过期前无法撤销，与“撤销授权后后续查询和修改停止”冲突。
- 引入 Redis 保存会话与任务进度：增加一个未经确认的运维依赖，并形成与 Oracle 不一致的第二份状态。

## Consequences

- 每个请求都回查 Oracle 的会话与授权；公司侧停用账号最迟在会话绝对寿命（8 小时）到期时生效。
- Oracle 的行锁与唯一约束成为采用竞争和保存结果核实的正确性基础，须在 `PLAN_TEST` 验证。
- 容器重启或数据库恢复后，会话全部失效，运行中的任务标记为已中断。
